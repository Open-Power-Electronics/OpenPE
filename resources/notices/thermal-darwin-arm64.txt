OpenPE Layout Thermal: bundled Gmsh 4.15.2 and Elmer 26.1 (darwin-arm64)

npm run thermal:prepare downloads the pinned GitHub release archive, checks its SHA-256 and size, then checks every file hash. It does not compile.
Maintainers rebuild that archive with npm run solvers:build-macos. scripts/build-thermal-macos.sh requires Apple clang 17.0.0, macOS SDK 26.2, CMake 4.4.5 and Homebrew GCC 16.2.0. That command is not part of ordinary setup.
The Elmer configuration is -DWITH_MPI=OFF -DWITH_ELMERGUI=OFF -DWITH_OpenMP=OFF -DWITH_Mumps=OFF -DWITH_UMFPACK=ON. OpenBLAS 0.3.13 is built from the pinned tarball; Homebrew OpenBLAS is not linked.
Gmsh is the official 4.15.2 MacOSARM SDK. Its gmsh -info output reports OpenCASCADE 7.8.1. Absolute toolchain rpaths are removed; Mach-O dependencies stay inside the bundle or in the macOS system libraries.
Runtime files, upstream solver and identified dependency source archives, build materials and license notices ship under resources/thermal/1.
The source archives remain unmodified; the source hash and original HTTPS URL are recorded in thermal-lock.json and manifest.json.
Gmsh is GPL version 2 or later with its upstream linking exception. Elmer modules retain their GPL/LGPL and individual dependency licenses.
libgfortran is covered by the GCC Runtime Library Exception in COPYING.RUNTIME. The tools and libraries can be replaced and rebuilt; reverse engineering for debugging modifications to LGPL libraries is permitted.
